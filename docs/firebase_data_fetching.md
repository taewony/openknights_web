# Firebase 데이터 조회 방식 요약

이 문서는 프로젝트의 Firebase 데이터 조회 방식에 대한 논의를 요약합니다.

## 질문: 데이터가 자주 바뀌지 않는데, 페이지 방문 시마다 Firestore에 다시 접근해야 하나요?

**답변:** 아니요, 항상 그럴 필요는 없습니다. Firestore SDK는 강력한 캐싱 기능을 내장하고 있어, 데이터를 한 번 가져오면 로컬에 캐시하고, 재요청 시 변경된 부분만 동기화하거나 캐시된 데이터를 즉시 반환하는 등 효율적인 데이터 관리가 가능합니다.

## 질문: 현재 프로젝트의 구현 방식은 어떤가요?

**결론: "데이터 한 번만 가져오기(one-time fetch)" 방식을 사용하고 있습니다.**

- **근거:** 프로젝트의 여러 곳에서 Firestore의 `getDocs` 또는 `getDoc` 함수를 호출하고 있는 것이 확인되었습니다.
    - **`getDocs` 사용처:** `contests/page.tsx`, `projects/page.tsx`, `users/page.tsx` 등
    - **`getDoc` 사용처:** `mypage/page.tsx`, `main-layout.tsx` 등

- **동작 방식:** 이 구현은 페이지에 진입하거나 컴포넌트가 렌더링될 때마다 Firestore에 데이터를 요청하여 한 번 가져옵니다. 즉, **현재로서는 페이지를 방문할 때마다 데이터를 다시 요청**하고 있습니다. 실시간으로 데이터가 자동 동기화되지는 않습니다.

- **참고:**
    - `react-firebase-hooks` 라이브러리가 사용되고 있으나, 이는 데이터 조회가 아닌 **인증 상태(`useAuthState`)를 실시간으로 감지**하는 데에만 사용되고 있습니다.
    - 비록 매번 요청이 발생하더라도, Firestore SDK의 캐시 정책 덕분에 서버 데이터에 변경이 없다면 실제 네트워크 트래픽은 최소화될 수 있습니다.
