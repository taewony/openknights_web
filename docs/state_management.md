# 프로젝트 상태 관리 방식 요약

## 질문: 이 프로젝트는 상태 관리를 어떤 방식으로 하고 있나요? 'React Query'를 사용하고 있나요?

**결론: 'React Query'는 사용하고 있지 않으며, 여러 방식을 조합하여 상태를 관리합니다.**

`package.json`과 코드 분석 결과, 이 프로젝트는 하나의 중앙화된 상태 관리 라이브러리(like Redux, Zustand)에 의존하기보다는, 목적에 따라 여러 도구를 조합하여 사용하는 방식을 채택하고 있습니다.

### 1. React 기본 Hooks (`useState`, `useContext`)

- **컴포넌트 지역 상태:** 각 컴포넌트 내부에서 필요한 간단한 상태는 `useState`를 통해 관리됩니다.
- **전역 상태:** 여러 컴포넌트에서 공유해야 하는 상태(예: 현재 로그인된 사용자 정보)는 `useContext`를 통해 관리됩니다.
    - **근거:** `src/contexts/AuthContext.tsx` 파일에서 사용자 인증 정보를 전역적으로 제공하고 있습니다.

### 2. 서버 상태 및 데이터 조회 (Firebase)

- **데이터베이스 조회:** Firestore 데이터베이스의 데이터를 가져올 때는 `getDocs`, `getDoc`과 같은 함수를 사용하여 **필요할 때 한 번만 가져오는(one-time fetch)** 방식을 사용합니다.
- **실시간 인증 상태:** `react-firebase-hooks` 라이브러리의 `useAuthState` 훅을 사용하여, 사용자의 **로그인/로그아웃 상태**는 실시간으로 감지하고 동기화합니다.

### 3. 폼(Form) 상태 (`react-hook-form`)

- 사용자 입력, 유효성 검사, 제출 등 복잡한 폼 관련 상태는 `react-hook-form` 라이브러리를 사용하여 전문적으로 관리합니다.
